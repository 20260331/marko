# Verify Rubric 与原始 Prompt 对照

原始 Prompt：翻译 Markdown 时，直接把文本重新解析会让译者输入改变链接、强调和代码结构，逐个 RawText 替换又没有句子上下文。增加本地化目录导出和应用接口，把可翻译文本与受保护的结构占位符分开，并在应用前校验译文仍保持原结构。

| rubric | 原始 Prompt 依据 |
|---|---|
| 1 | “翻译 Markdown”是在现有 Markdown 能力上增加功能，故要求既有解析/渲染行为不回归。 |
| 2 | 直接对应“增加本地化目录导出接口”和“逐个 RawText 替换又没有句子上下文”。 |
| 3 | 直接对应“把可翻译文本与受保护的结构占位符分开”，并按 Prompt 明示的链接、强调、代码验收。 |
| 4 | 直接对应“增加……应用接口”，且要求译文确实能回写为 Markdown。 |
| 5 | 直接对应“在应用前校验译文仍保持原结构”，占位符校验属于该要求的可观察部分。 |
| 6 | 对“仍保持原结构”的严格验收：正常译文即使包含 Markdown 定界符，也不能在最终序列化后破坏链接或强调结构。没有增加 Prompt 之外的新功能。 |
| 7 | “应用前校验”意味着校验失败不能先应用一半；这是对校验时机的严格但直接的验收。 |

未纳入强制 rubric 的观察项：JSON/TMS 交换、GFM/脚注扩展支持、错误消息具体措辞、文件或类名。这些虽由实现提供，但不是原始 Prompt 的明确要求，因此不作为验收门槛。
